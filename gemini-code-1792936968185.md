# QuickNotes API Design

## Endpoints Overview

| Method | Path | Description | Success Status |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/notes` | List notes for the authenticated user | `200 OK` |
| `POST` | `/api/v1/notes` | Create a new note | `201 Created` |
| `GET` | `/api/v1/notes/{id}` | Retrieve a specific note by ID | `200 OK` |
| `PUT` | `/api/v1/notes/{id}` | Update an existing note | `200 OK` |
| `DELETE` | `/api/v1/notes/{id}` | Delete a note | `204 No Content` |
| `GET` | `/api/v1/tags` | List all tags created by the user | `200 OK` |

---

## Examples

### 1. Create a Note
* **Method & Path:** `POST /api/v1/notes`
* **Request Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
* **Request Body:**
```json

  "title": "Grocery List",
  "body": "Milk, eggs, bread, and coffee beans.",
  "tags": ["personal", "shopping"]

## Error Status Codes & Handling
The API uses standard HTTP status codes and returns a structured JSON error body for troubleshooting.

400 Bad Request: Malformed JSON or validation failed (e.g., missing title).

401 Unauthorized: Missing or invalid authentication token.

403 Forbidden: Authenticated user lacks permission to access the resource.

404 Not Found: The requested note or resource does not exist.

500 Internal Server Error: Unexpected server-side failure.
Example Error Response Body (400 Bad Request)
{
  "error": {
    "code": "VALIDATION_ERROR",
    "status": 400,
    "message": "The 'title' field is required and must not exceed 100 characters.",
    "details": [
      {
        "field": "title",
        "issue": "Field is required"
      }
    ]
  }
}
